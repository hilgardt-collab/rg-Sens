## HIGH severity (13)

### H1. Update thread panics at startup shortly after boot
`src/core/update_manager.rs:376` and `:625` — `last_update: Instant::now() - interval` panics
("overflow when subtracting duration from instant") when system uptime < panel interval (Linux `Instant`
is CLOCK_MONOTONIC anchored at boot). Autostart at login ~30s after boot with e.g. a 60s+ Claude panel →
`add_panel` panics inside `rt.block_on` (`src/main.rs:1294`) → update thread dies → **no panel ever updates, silently**.
Fix: `now.checked_sub(interval).unwrap_or(now)` or a "due immediately" flag.

### H2. Cancelling the close-with-unsaved-changes dialog kills the app's update loop
`src/main.rs:1235-1280` + `src/ui/config_helpers.rs:72-75` — `connect_close_request` runs
`close_all_dialogs()`, `update_manager.stop()`, and `css_template_shutdown()` **before** checking `is_dirty`
and showing Save/Don't Save/Cancel. Clicking **Cancel** leaves the window open but every panel frozen forever,
dialogs force-closed, web backends terminated. Move stop/shutdown into the non-dirty branch and the dialog callbacks.

### H3. Non-atomic config save can destroy the dashboard layout
`src/config/settings.rs:115` (also `:142`) — plain `std::fs::write` (truncate-then-write), no temp+rename,
no fsync, no backup. Crash/power-loss mid-write truncates config.json; next launch falls back to defaults;
next save **overwrites the recoverable file with an empty default layout**. Same pattern in
`src/config/defaults.rs:170` (default styles). Fix: write temp file, fsync, atomic rename.

### H4. Color picker Cancel commits the color anyway
`src/ui/custom_color_picker.rs:1512-1519, 1565-1571` — OK and Cancel both just `dialog.close()`, and
`connect_close_request` unconditionally resolves with `Some(*current_color)`. `pick_color()` can never
return `None` — Cancel (or WM close) applies the experimental color and fires `on_change`. Affects every
color swatch in the app (ColorButtonWidget, ThemeColorSelector).

### H5. First-frame animation overshoot in bar + LCARS + all nine themed combos (copy-pasted bug)
- `src/displayers/bar.rs:117-123`
- `src/displayers/lcars_combo.rs:631-650`
- `src/displayers/combo_displayer_base.rs:524-575` (used by cyberpunk, material, industrial, retro_terminal,
  fighter_hud, synthwave, art_deco, art_nouveau, steampunk via `combo_generic.rs:502-509`)

The animation timestamp (`last_frame_time` / `last_update`) is only refreshed **while** an animation is in
progress, so the first animating frame after any pause measures `elapsed` since the previous animation ended
(0.5s–minutes). With default speeds there is no overshoot clamp → `delta` exceeds the gap several-fold and
values visibly slam past target on every data update. Correct patterns to copy: `arc.rs` (per-tick timestamp
refresh) and `cpu_cores.rs:180` (`(speed*delta).min(1.0)` clamp).

### H6. Analog clock freezes when smooth seconds is off
`src/displayers/clock_analog.rs:356-429, 325-351` — `update_data` never sets a dirty flag, and the tick
returns `true` only for flash toggles or `smooth_seconds && show_second_hand`. Disable "Smooth Second Hand"
(or hide the second hand) → the clock face never redraws: hands frozen, timer countdown/alarm icon stale.

### H7. Triggered alarms auto-dismiss after ~1 second
`src/core/timer_manager.rs:528-533` — the re-arm branch clears `triggered_alarms` + `alarm_sound_played`
on the first tick after the trigger second. The blink indicator lasts ~1s and the click-to-dismiss handler
(`grid_layout.rs:920-940`) becomes unusable while sound may still play. Re-arm should clear only
`last_alarm_check`; triggered state should persist until dismissed (as Finished timers do).

### H8. Ctrl+drag copy of a copy is never registered with the UpdateManager
`src/ui/grid_layout.rs:~2963` (nested-copy path, block 2893-3207) — pushes the panel into the Vec and marks
cells but omits `update_manager.queue_add_panel` (the other two copy paths do call it: 2119, 4232).
Second-generation copies render once and freeze until restart.

### H9. New network interfaces are invisible forever
`crates/sources/src/network.rs:250` — the shared `Networks` list is built once at startup; sysinfo 0.31's
`refresh()` updates existing entries only (`refresh_list()` is never called). VPN `tun0`, USB tether,
docker/hotspot interfaces created after launch report zeros forever.

### H10. Disks: hotplug invisible + wrong numbers after unmount
`crates/sources/src/disk.rs:242` — same pattern: `refresh()` only statvfs-refreshes startup disks and only
updates `available_space` (`total_space` frozen). (a) filesystems mounted after launch are permanently N/A;
(b) after an unmount, statvfs on the stale mountpoint succeeds against the **parent** fs → plausible but
wrong free-space numbers, silently.

### H11. CSS template mapping rows corrupt neighbors after row removal
`src/ui/css_template_config_widget.rs:675-690, 800-821` (stale captures at 575-593, 615-636, 650-665,
763-789, 866-882) — remove handlers delete mapping entries without rebuilding remaining rows; surviving
rows keep construction-time indices. Remove row 0 of 3 → editing visible row 2 writes into the mapping
below it; last row's edits silently no-op. Remove also renumbers `m.index = i`, silently re-targeting
`{{N}}` placeholders. (gradient_editor.rs / text_line_config_widget.rs rebuild after removal — copy that.)

*(H4/H11 counted with the two agent-reported HIGHs from grid/dialogs H2/H8 and core H1/H7 = 13 total
including H5 spanning 3 files.)*
